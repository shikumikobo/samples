# Site Manager（現場管理アプリ）の見本

架空の工務店（従業員10人）の現場管理アプリです。同じデータを、**入る人によって見え方が変わる**様子を、ブラウザの中だけで試せます。

- ログインと5種類の人（社長・社員・職人・お客さん・協力業者）
- 職人には担当の現場だけが見え、金額は見えません
- お客さんと協力業者には、許可された分だけを見せる**専用ページ**があります
- 「だれが何を見られるか」は、画面ではなく**データベースの側**で守っています

スプレッドシートでは足りなくなった会社が、WEB アプリに移るときの見本です。

## まず試す（3分）

1. 最初の画面で、**社長（山本 誠）**として入ります。現場の一覧、金額、見積、変更の履歴が見えます。
2. 画面の上の「役割」で、**職人（大川 健二）**に切り替えます。現場が担当の3件だけになり、金額と見積が消えます。
3. 「役割」を**お客さん（田中 一郎）**に切り替えます。専用ページに移り、自分の現場の進み具合・予定・共有されたファイル・見積だけが出ます。
4. もう一度**社長**に戻り、現場の詳細の「外部への共有」タブで、許可を外します。お客さんに戻すと、その現場が消えています。
5. 画面の上の「最初に戻す」で、いつでも元のデータに戻せます。

## だれが何を見られるか

| | 社長 | 社員（営業・事務） | 職人 | お客さん | 協力業者 |
|---|---|---|---|---|---|
| 現場 | すべて | すべて | 担当の現場だけ | 許可された現場だけ | 許可された現場だけ |
| 金額・見積 | 見える | 見える | **見えない** | 許可された現場の提出・承認済みの見積 | **見えない** |
| 予定 | 全員分 | 全員分 | 自分の分だけ | 許可された現場の予定 | 許可された現場の予定 |
| ファイル | すべて | すべて | 担当の現場のすべて | 「お客さんに共有」したものだけ | 「協力業者に共有」したものだけ |
| ユーザー管理 | できる | できない | できない | できない | できない |
| 変更の履歴 | 見える | 見えない | 見えない | 見えない | 見えない |

くわしい表は [docs/permissions.md](docs/permissions.md) にあります。

## できること／作っていないこと

できること

- 現場の一覧（状況のタブ・検索・担当者や期日での絞り込み）と、現場の詳細（概要・予定・見積・ファイル・外部への共有・履歴）
- 今日の予定と、対応漏れの警告（担当が決まらない・着工や完工が遅れている）
- 担当者ごとの週の予定
- 見積の明細と、消費税の計算（合計に1回・10%・切り捨て）
- ファイルを「社内のみ／お客さん／協力業者／両方」に分けて共有
- ユーザー管理（社長だけ）と、変更の履歴（だれが・いつ・何を）
- 外部の専用ページ、スマホの画面、ホーム画面に入れて使える PWA

作っていないこと

- 請求・入金・通知（メールや LINE）・レシート・決済
- 本物のファイルの保存（図面や写真は、架空の絵です）
- パスワードによるログイン（デモは、人を選ぶだけで入ります）

## 画面

| 画面 | 場所 | 見られる人 |
|---|---|---|
| ログイン（人を選ぶ） | `/` | だれでも |
| 今日 | `/today/` | 社内の人 |
| 現場の一覧 | `/sites/` | 社内の人 |
| 現場の詳細 | `/sites/detail/?id=現場番号` | 社内の人 |
| 担当者ごとの予定 | `/schedule/` | 社内の人 |
| ユーザー管理 | `/users/` | 社長 |
| 外部の専用ページ | `/portal/` | お客さん・協力業者 |

お客さんと協力業者が社内の画面を開くと、専用ページに戻ります。

## 動かし方

Node.js が入っていれば、次で動きます。

```bash
cd app
npm install
npm run dev
```

ブラウザで `http://localhost:3000` を開きます。

テスト

```bash
# 画面と計算のテスト（app で）
npm test

# 権限のテスト（site-manager の直下で）
node --test "db/tests/*.test.mjs"
```

公開用のファイルを作る

```bash
cd app
npm run build   # out/ に静的なファイルができる
```

`out/` を、静的なファイルを置ける場所（Cloudflare Pages など）に置けば公開できます。サーバーは要りません。

## デモのしくみ

- データは**ブラウザの中**にあります（PGlite という、ブラウザで動くデータベース）。サーバーに送りません。
- 費用はかからず、止まらず、荒らされません。
- 「最初に戻す」で、架空のデータに入れ直します。
- 初めて開くときは、準備に数秒かかります。

## 使っているもの

- Next.js（静的な書き出し）・React・TypeScript
- PGlite（ブラウザの中の PostgreSQL）
- Vitest（画面と計算のテスト）と、権限のテスト（SQL を実際に流して確かめる）
- PWA（ホーム画面に追加、機内モードでも開く）

## フォルダ

```
site-manager/
├─ app/                画面（Next.js）
│  ├─ src/app/         画面ごとのフォルダ（フォルダ名が URL になる）
│  ├─ src/features/    見積の計算・ファイル・共有・履歴・対応漏れなどの部品
│  ├─ src/lib/         ブラウザ内のデータベース・役割の選択・権限の読み出し
│  └─ public/          アイコン・サービスワーカー・架空のファイル
├─ db/                 データベースの定義（表・権限の判定・RLS・履歴・架空のデータ）と権限のテスト
├─ docs/               権限の表・設計の図・台帳との対応
└─ scripts/            架空のファイルを作る道具
```

設計の図は [docs/architecture.md](docs/architecture.md) にあります。

## スプレッドシートからの移行

同じ工務店のスプレッドシートの台帳（顧客・現場・見積・予定など）と、列をそろえてあります。台帳の列とこのアプリの列の対応は、[docs/ledger-mapping.md](docs/ledger-mapping.md) の表のとおりです。台帳を CSV にして取り込めば、現場や見積をそのまま移せます（取り込みの処理は、この見本には入れていません）。

## 本番にする場合

この見本はデモなので、ブラウザの中だけで動きます。本番では次のように変えます。

- データベースを **Supabase** に置き、同じ定義（`db/`）を流します。権限の判定は、そのまま使えます。
- ログインを、メールとパスワード（または招待）にします。「いまの利用者」と「役割」の取り出しを、Supabase の認証に置き換えます（`current_user_id()`・`current_app_role()` の2つ）。
- ファイルを、Supabase の Storage（社内用と外部用の置き場）に保存します。
- バックアップを、Supabase の毎日の自動バックアップにします。

Supabase での確認の手順は、準備中です（[docs/supabase-check.md](docs/supabase-check.md)）。
