# Booking CRM（予約と顧客管理）の見本

予約制のお店と教室のための、予約と顧客管理のアプリです。**サロンと教室のどちらにも使える1つの作り**で、画面の隅の切り替えで、架空のネイルサロンと架空の料理教室の両方を試せます。データはブラウザの中だけにあります。

- お客さんが、メニューと日時を選んで予約する（空き枠の表示、二重予約の防止）
- お店の人が、予約表・顧客のカルテ・「販売促進」の一覧で管理する
- 体験プラン（0〜3,000円の特別メニュー）を、通常の予約と同じ扱いで管理する
- 日時の変更・キャンセルは、新しい枠を先に確保してから元を空ける（取れなければ元のまま）

スプレッドシートや電話・LINE での予約が回らなくなった個人店・小さな教室が、WEB アプリに移るときの見本です。

**年間の削減（想定）**：予約の受け付け（電話・LINE の往復と台帳への書き写し）月60件 × 5分 → 年約60時間、「販売促進」の連絡先の洗い出し 月1時間 → 10分で年約10時間、合わせて年約70時間 × 時給2,000円 ＝ 約14万円分。加えて、夜や休みの時間の予約を逃さない（翌日の返事を待たせない）。件数は小さな1店舗の想定で、お店ごとに変わります

## まず試す（3分）

1. 画面の上で **サロン**を選び、**お客さん**のまま「メニューを選ぶ」。**はじめてのジェルネイル体験（初回限定）** を選び、担当と日時を選んで予約します。
2. もう一度、同じ人で体験プランを予約しようとすると、**初回限定**のため断られます。
3. 「**私の予約**」で、予約の日時を変えてみます（満席の枠には移れず、元の予約は残ります）。
4. 画面の上で **お店**に切り替えます。「今日」と「予約表」に予約が出ています。「来店済み」にすると、顧客のカルテの履歴に残ります。
5. 「販売促進」の一覧で、前回の来店から日が経ったお客さんを確認し、連絡の文を作ってコピーできます。
6. 画面の上で **教室**に切り替えます。同じ作りで、1回の枠に複数人（定員）が入る予約になり、言葉も「コース・講師・生徒・出席」に変わります。
7. 画面の上の「最初に戻す」で、いつでも架空のデータに戻せます。

## 対象にしている業種

| 区分 | 業種の例 |
|---|---|
| そのまま使える（1回に1人） | 美容室、ネイル、まつげ、エステ、リラクゼーション、整体（自費のみ）、マッサージ、ペットのトリミング、パーソナルトレーニング、カウンセリング、個人レッスン |
| 枠の定員の設定だけで使える（1回ごとの参加） | ヨガ、ダンス、料理教室、グループレッスン、ワークショップ、体験会、フィットネススタジオ |

月謝・回数券・振替・オンライン決済・部屋や設備の予約などは、ご相談のうえ追加で対応します。

## できること／作っていないこと

できること

- メニュー（所要時間・料金）、担当者（教室は講師）ごとの営業時間と休みから、15分刻みの空き枠を計算
- 予約の受付・変更・キャンセル。同じ担当の重なる時間と、教室の定員は、データベースの関数と排他制約で守る
- 同じ日に取れるのは2件まで、直前（2時間前まで）・先すぎる（60日先まで）予約は取れない、変更・キャンセルは前日の終わりまで（お店の人は過ぎても直せる）
- 体験プランの「初回限定」（電話番号またはメールが同じ人は1回だけ）と、体験から通常のメニューに来た人の集計
- 顧客のカルテ（お店のメモ・注意事項・来店履歴）、変更の履歴（だれが・いつ・何を）
- 「販売促進（教室は再受講）」の一覧と、連絡の文の作成（コピーするだけ）
- スマホで使える画面、ホーム画面に入れて使える PWA
- 見た目の設定：色（ローズ・モーヴ・セージ）と見出しの書体（明朝・丸ゴシック・ゴシック）を、お店の「設定」画面で変えられる（サロンの初期はローズ＋明朝、教室の初期はセージ＋丸ゴシック。サロン／教室ごとにブラウザに覚え、お客さんの画面にも反映される）

作っていないこと

- 決済（支払いは当日お店で）・請求書・領収書、メールや LINE の本物の送信
- 振替・回数券・月謝、部屋や設備の予約、オンラインのログイン
- 本物の写真（画像は雰囲気だけの絵で、金額は入れていません）

## だれが何を見られるか

| | お客さん | お店 |
|---|---|---|
| 予約 | 自分の予約だけ | すべて |
| 顧客の情報 | 自分の名前・連絡先だけ | すべて（お店のメモ・注意事項を含む） |
| お店のメモ・注意事項 | **見えない** | 見える |
| 変更の履歴 | 自分の予約のぶんだけ | すべて |
| 予約の変更・キャンセル | 前日の終わりまで | いつでも |
| 来店済み・無断欠席にする | できない | できる |
| 設定（メニュー・開催日・担当・営業時間・休み） | できない | できる |

「だれが何を見られるか」は画面ではなく、**データベースの側**（役割と行の制限）で守っています。

## 画面

| 画面 | 場所 | 使う人 |
|---|---|---|
| 最初の画面（サロン／教室、お客さん／お店の選択） | `/` | だれでも |
| メニューの選択 → 担当と日時 → 確認 → 完了 | `/book/` → `/book/time/` → `/book/confirm/` → `/book/done/` | お客さん |
| 私の予約（確認・変更・キャンセル） | `/my/` | お客さん |
| 今日 | `/today/` | お店 |
| 予約表（日・週） | `/calendar/` | お店 |
| お客さん（生徒）の一覧とカルテ | `/customers/`・`/customers/detail/?id=` | お店 |
| 販売促進 | `/return/` | お店 |
| 設定（メニューの追加・削除・画像、教室の開催日、担当の編集・追加、営業時間、休み、見た目） | `/settings/` | お店 |

## 動かし方

Node.js が入っていれば、次で動きます。

```bash
cd app
npm install
npm run dev
```

ブラウザで `http://localhost:3000` を開きます。

テスト

```bash
# 画面と計算、DB を通したテスト（app で）
cd app && npm test

# データベース（表・関数・権限・履歴）のテスト（booking-crm の直下で）
node --test "db/tests/*.test.mjs"

# 架空のデータの検査（booking-crm の直下で）
python data/validate.py

# 画面の確認（全URL・スマホ幅、サロンの主な流れ。開発サーバーか out/ を配信したサーバーを先に起動）
cd app && python -I scripts/smoke.py --base http://localhost:3000
```

公開用のファイルを作る

```bash
cd app
npm run build   # out/ に静的なファイルができる
```

画面の作り：
- お客さん側（PC・幅 760px 以上）：上にデモの細い帯 → お店の名前の大きな見出し → 丸いメニュー（予約する／私の予約）→ 内容。
- お客さん側（スマホ）：軽い上の帯と、下に固定したタブ。片手で押せます。
- お店側：PC・スマホとも、白い細い帯にメニュー（スマホは下に固定のタブ）。情報を詰めて見せます。
- お客さんの日にち選びは、月ごとのカレンダー（空きのある日だけ押せる）です。
- 教室の開催日は、設定の「開催日」で、日にち限定（1回だけ）・毎週（同じ曜日）・毎月（同じ日付。31日などは月末に寄せる）から選んで足せます。毎週・毎月は「いつまで」の期限（はじめの日から1年以内）まで、まとめて足します。くり返しは、期限の変更（延ばす・縮める）と、やめるができます。予約の記録がある日は消えず、日にち限定として残ります。はじめの状態は、日にち限定5・毎週3・毎月1です。
- 予約表（お店）は週の表示が初期で、今日の列は色が変わります。
- 画面の配置を切り替える設定はありません。色と書体だけ、設定画面で変えられます。

`out/` を、静的なファイルを置ける場所（Cloudflare Pages など）に置けば公開できます。サーバーは要りません。

## デモのしくみ

- データは**ブラウザの中**にあります（PGlite という、ブラウザで動くデータベース）。サーバーに送りません。
- 費用はかからず、止まらず、荒らされません。
- サロン／教室を切り替えると、その業種の架空のデータで作り直します。「最初に戻す」も同じ処理です。
- デモの「今日」は 2026-11-09（月）に固定です。

## 使っているもの

- Next.js（静的な書き出し）・React・TypeScript
- PGlite（ブラウザの中の PostgreSQL。排他制約に `btree_gist` を使用）
- Vitest（画面と計算、DB を通したテスト）、Node のテストランナー（DB のテスト）、Playwright（画面の確認）
- PWA（ホーム画面に追加）

## フォルダ

```
booking-crm/
├─ app/        画面（Next.js）。src/app が画面、src/features が予約・お店の部品、src/lib が DB の接続・言葉の辞書・見た目の設定（theme.ts）、src/styles が色と書体の定義
├─ db/         データベースの定義（表・関数・権限・履歴）、架空のデータ（seed）、テスト
├─ data/       架空のデータの元（サロン・教室の JSON）、画像の元、検査
├─ scripts/    JSON から seed を作る道具
├─ docs/       作る側の取り決め（表・関数・エラーコード・役割・画面）
└─ hearing.md  作る前の確認事項（決めたことの一覧）
```

## 本番にする場合

この見本はデモなので、ブラウザの中だけで動きます。本番では次のように変えます。

- データベースを **Supabase** などのサーバー側に置き、同じ定義（`db/`）を流します。二重予約と定員の防止は、サーバー側の関数でそのまま使えます（本番では、同時に予約が入っても重ならないことを、サーバー側で確かめます）。
- お客さんのログイン（または予約番号での確認）、予約や来店の促しの通知（メール・LINE）を足します。
- 画像は、お店の実際の写真に差し替えます。
- 色と見出しの書体の初期値を、お店ごとに決めます（見本はサロン＝ローズ＋明朝、教室＝セージ＋丸ゴシック）。お店の人が、設定画面から変えることもできます。
- バックアップを、サーバー側の自動バックアップにします。

## お客様ごとに確認すること

見本は標準の形で作っています。次は店ごとに決まりが違うため、案件ではヒアリングシートで確認し、標準から複雑になる分は追加の見積りとして相談します。

| 項目 | 見本での形 | 複雑になる例 |
|---|---|---|
| 変更・キャンセルの期限 | 前日の終わりまで | 業種や曜日ごとの期限、キャンセル料、無断欠席の扱い |
| 同じ人の判定・体験の初回限定 | 電話番号またはメール | 家族での共有、会員番号 |
| 振替・回数券・月謝 | 作らない（予約変更で対応） | 振替の決まり、回数券の残数、月謝の請求 |
| 枠の定員 | 枠ごとに1つ | 講師や部屋ごとの違い、補欠・待ち |
| 体験プラン | 0〜3,000円の特別メニュー1つ | 回数・期間の制限、複数のプラン |
| 通知 | 本物は送らない | LINE・メールの自動送信 |
| 支払い | 当日お店で | オンライン決済、領収書 |
| 営業時間・休み | 曜日ごと・担当者ごと | 祝日の自動判定、臨時休業の一括反映 |
| 色・書体 | 3色・3書体から選ぶ（初期はサロン＝ローズ＋明朝、教室＝セージ＋丸ゴシック） | お店のロゴや決まった色に合わせた配色、専用の書体 |

## 注意

登場する店・人・電話番号・メール・金額は、すべて架空です。
